# 显示与触摸组件开发规范

本规范约束新建或修改屏幕、触摸及 LVGL 粘合组件时的**稳定设计边界**。它不认定某块开发板已接入某种屏幕；接口、像素格式与组件测试应分别写清，板级接线、初始化表及性能参数须经过实板验证后才能写成已验证结论。通用的错误码、注释、版本与发布要求仍以 [组件维护约定](../CONTRIBUTING.md) 为准；用户侧接线步骤见[显示与触摸组件接入指南](display-components.md)。

## 组件边界与命名

- 每个显示控制芯片维护独立仓库 `stm_lcd_<芯片型号>`（例如 `stm_lcd_st7789`、`stm_lcd_st7796`）；每个触摸控制芯片维护独立仓库 `stm_lcd_touch_<芯片型号>`（例如 `stm_lcd_touch_ft5206`）。不将不同芯片的初始化序列和协议集中在一个大 `.c` 中，也不为组件增设仅做转发的 `stm_display` 或 `stm_touch` 仓库。
- 芯片组件负责该型号的命令、窗口、像素写入和触点解码；不拥有 STM32 时钟、GPIO、HAL 句柄、互斥锁或背光电源，也不直接包含某个具体开发板的引脚映射。板级代码负责传输、复位、延时与供电；用户按实际接口选择 SPI、RGB/LTDC 等板级实现。**SPI 芯片驱动不能冒充 RGB/LTDC 显存驱动。**
- `stm_lvgl_port` 只连接 LVGL 的 display / input 回调与用户提供的绘图/触摸函数；不包含单一芯片的初始化表，不替应用初始化外设、安排任务或隐式启动定时器。依赖 LVGL 9 的版本范围应在 README 和 CMake 中明确。
- 芯片配置由调用者传入；清楚标注实例与回调上下文、帧缓冲区的生命周期。保持组件可在没有 RTOS、RTT 和日志组件的情况下使用。第三方 LVGL 与 ST HAL 按各自许可由用户工程提供。

## 回调契约与兼容性

- 面板命令与数据采用 `tx_param(context, command, data, length)`；像素写入采用 `tx_color(context, command, pixels, length)`。长度以**字节**计，`tx_color` 必须在一笔独占总线事务内发出 RAMWR 命令与全部像素，直到完成或报错才释放 CS/锁。回调若同步返回，必须在返回前消费完像素；将来添加 DMA 异步接口时必须另行定义完成通知和缓冲归属，不复用同步契约冒充完成。
- 矩形范围统一为 `[x1, x2) × [y1, y2)`；明确逻辑宽高、偏移、旋转、色序和线上 RGB565 高低字节顺序。LVGL 的坐标若采用闭区间，在粘合层转换一次，不在板级和芯片层重复转换。不得凭厂商的通用实验默认所有模组使用同一分辨率或 MADCTL。
- 触摸组件由板级提供寄存器读取回调；在文档中区分设备的 **7 位 I²C 地址**和 STM32 HAL 接口所需的左移地址。通信/畸形帧失败清空本次缓存；GT9271 无新帧时保留上一状态，仅有效零点帧释放；点数、边界、方向交换和镜像必须有明确约束。无触摸屏时 LVGL 粘合层应允许不注册输入设备。
- 文档必须说明阻塞传输不得从中断调用、共享总线须在整笔事务外加锁、DMA 与 DCache 的一致性由哪个层负责，以及异常时是否仍通知 LVGL 释放缓冲。不能把编译通过等同于传输时序或颜色正确。

## 公开文档与最小示例

- 每个独立仓库以中文 `README.md` 为默认入口，包含适用芯片、支持边界、最小 API、依赖、CMake 链接、错误状态和测试范围；如需英文，可另设 `README.en.md` 并从中文首页互链。中文接入指南同时链接各组件的独立示例。
- 每个组件保留 `examples/stm32_hal/`：中文 README 说明 CubeMX 选项、HAL 句柄和引脚替换项、源码加入应用目标的方法，提供调用芯片初始化/绘图或读取触点的 C 示例。粘合层示例展示 `lv_init`、注册、tick、handler、绘图和可选触摸。未确认实物时，用占位符要求用户填写，不写虚构的 GPIO 或声称实板已验证。
- 可复制到既有 CubeMX 工程的板级适配示例允许 `example.c` / `example.h`，不必定义另一个 `main()`；若提供独立可运行固件工程，仍按通用规范给出 `main()` 与 `board_init()`。示例源码不能默默编入组件库本体。

## 测试、支持声明与发布门槛

| 阶段 | 必须留下的证据 | 可以声明 |
| --- | --- | --- |
| 主机检查 | 芯片命令/坐标/字节数/错误路径测试；LVGL 回调与缓冲释放测试；CMake 和示例语法编译 | 仅「主机测试通过」「指定目标编译通过」 |
| 开发板实测 | 屏幕与触摸芯片的实物标识、板版本、连接和电源、固件版本、SPI/I²C 参数、测试日志及现象 | 仅针对**实测型号、方向、分辨率、配置**声明支持 |
| 发布版本 | 回归主机测试和对应实板项目，修订 README，完成通用规范的接口与错误码对齐，GitHub/Gitee 同步 tag，并按通用规范创建 GitHub Release | 对已验证配置声明正式版本 |

首次实板测试时重点记录：上电复位和初始化、整屏/边界/多块绘制、颜色与方向、重复刷新与长时间运行；若带触摸，还要覆盖单点、松手、边界、方向、通信失败后的恢复；若启用 LVGL，检查持续刷新、部分刷新、缓冲生命周期和内存占用。发生错误须保留首个失败条件与日志，修复后重新测试。实际面板芯片、触摸型号、时序、引脚和最高可靠速率只能在核实硬件后填入对应组件的 README 或板级示例，不提前固化到通用规范。

## API 与生命周期统一

芯片使用 lcd_<型号>_handle_t、lcd_touch_<型号>_handle_t，LVGL 使用 lvgl_port_handle_t；配置和相关类型采用相同前缀，公开头文件不暴露实例字段。统一 create(config,&handle)/delete(&handle)、stm_err_t 返回值和回调错误传递，不保留 v0.1.0 的 int/负数错误包装。

创建要求输出为空，以 calloc/free 管理控制对象、复制配置，芯片 create 不访问硬件；重复创建拒绝且保留原对象。失败回收本次资源，删除成功清空句柄。HAL、总线、帧缓冲和回调上下文由应用持有。面板统一 reset/init，ILI9881C init 不再隐式复位；初始化失败保持未就绪，绘图失败可能部分写入，不回滚、不自动重试。

LVGL port 默认仍是同步 PARTIAL RGB565。get_display/get_indev 返回借用对象，禁止删除或替换 user_data；get_status 查询组件回调错误。应用自行替换 DIRECT flush 时独立管理错误状态，不将其误写入 port 内部字段。删除必须先停止所有 LVGL/组件并发调用。

## 当前验证与发布状态

6 个组件的软件接口迁移完成后，必须通过生命周期、参数、错误路径和 C11/C++17 主机检查，使用真实 HAL/LVGL 头文件编译中文示例，并验证依赖复用、固定下载和离线失败。当前新增接口尚未进行实板回归，不因为旧版本曾实测就声明新提交已经实板通过。

v0.1.0 的 ILI9881C、GT9271、LVGL port 配套 H757 示例已有实板验证；ST7789、ST7796、FT5206 仅主机验证。此次迁移本轮不烧录、不推送、不发布 tag/Release，后续实板回归通过后发布 v0.2.0，旧标签不移动。examples/stm32_hal 是移植用板级代码，不是包含完整 .ioc 的固件工程。
